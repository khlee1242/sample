# kedg견적관리

PRD.md 전체 범위를 목표로 개발 중입니다. 현재는 **직원 로그인과 견적 초안 저장** 단계입니다.

## 실행

Windows에서는 **`시작.cmd`를 더블클릭**하세요. 처음 실행할 때 필요한 패키지와 로컬 초기 설정을 준비한 뒤 서버를 실행합니다. 표시된 주소를 열고, 초기 로그인 정보는 `.data/initial-admin.txt`에서 확인하세요. 종료할 때는 실행 창에서 Ctrl+C를 누릅니다.

아래 명령은 터미널에서 직접 실행할 때 사용합니다.

Node.js 24 및 pnpm이 필요합니다. Codex 내장 런타임도 실행 스크립트에서 탐색합니다.

```powershell
./scripts/project.ps1 install
./scripts/project.ps1 setup
./scripts/project.ps1 dev
```

브라우저에서 http://127.0.0.1:3000 에 접속합니다. 초기 관리자 로그인 정보는 setup이 생성하는 `.data/initial-admin.txt`에서 확인합니다. 비밀번호는 무작위 생성하며 콘솔·소스에 기록하지 않습니다. 로그인 후 ‘계정 보안’에서 비밀번호와 인증 앱(TOTP)을 설정하세요. 공개 회원가입은 차단되어 있습니다.

이번 개발 세션에서는 setup 실행 승인이 거절되어 `.env.local`, 로컬 업무 DB, 초기 관리자 파일을 생성하지 않았습니다. 위 명령을 사용자 터미널에서 실행해야 로컬 로그인이 가능합니다.

거래처·현장 등록 → 공사명/거래처/현장 선택 → 견적 입력 → ‘견적 저장’ → 저장 목록에서 다시 열기 순서로 확인합니다. 현재는 **수동 저장**이며 자동저장은 후속 작업입니다. 동시 수정 충돌 시 현재 입력을 보관한 뒤 저장 목록에서 다시 여세요.

기본 개발 DB는 PGlite로 `.data/pglite`에 저장됩니다. **동일 디렉터리를 두 프로세스가 동시에 열면 안 됩니다.** 서버를 종료한 상태에서 setup·db:migrate를 실행하세요. 초기 설정을 재실행해도 기존 계정은 유지합니다. 이 개발 단계에서는 검증용 데이터를 사용하세요.

운영용 PostgreSQL은 `.env.local`의 `DATABASE_URL`로 연결합니다. 운영 연결은 아직 실증하지 않았습니다. 로컬 PGlite에서 PostgreSQL로 데이터를 자동 이관하지 않으며 별도 이관 검증이 필요합니다. 운영의 비밀키·HTTPS URL·백업은 배포 전에 따로 구성해야 합니다.

Vercel에서는 DB 설정 전에도 홈에서 **계산 미리보기**를 사용할 수 있습니다. 이 화면은 저장하지 않습니다. 로그인·견적 저장을 켜려면 지속형 PostgreSQL을 준비하고 `DATABASE_URL`, 32자 이상의 무작위 `BETTER_AUTH_SECRET`, 배포 주소를 담은 `BETTER_AUTH_URL`을 Vercel 환경변수로 설정한 뒤 SQL 마이그레이션과 초기 관리자 등록 절차를 별도로 검증해야 합니다. PGlite 파일 DB는 서버리스 운영용으로 사용하지 않습니다.

```powershell
./scripts/project.ps1 test
./scripts/project.ps1 typecheck
./scripts/project.ps1 build
```

## 현재 구현

- 한국어 견적 입력 및 행 추가·삭제, 단순/상세 계산 미리보기.
- Decimal 기반 금액·할인·VAT·간접비·이윤·마진 계산과 입력 검증.
- Better Auth 기반 비밀번호·DB 세션·TOTP/복구 코드·로그아웃·요청 횟수 제한.
- Drizzle PostgreSQL 스키마·SQL 마이그레이션, 파일 기반 개발 DB.
- 거래처·현장 등록 및 조회, 인증된 견적 생성·수정·다시 열기 API.
- 저장 시 서버 재계산, 낙관적 잠금, 같은 저장 요청 재시도 중복 방지, 트랜잭션 감사.
- 조회자 응답에서 원가·마진 제거, 조직 범위 검사, 동일 출처 쓰기 검증.
- 제출·승인 상태의 순수 도메인 규칙, 고객 DTO 허용 목록.
- 계산·인증·API·롤백·동시 수정·파일 DB 재열기 테스트.

화면 계산은 미리보기이며 저장 시 서버가 같은 엔진으로 확정합니다. 초안은 첫 견적 차수만 지원하며 제출·승인 서비스는 아직 연결하지 않았습니다. 2단계 인증은 사용자 설정 방식이며 전 직원 강제 등록 정책은 후속 작업입니다.

미구현: 계정 관리 UI, 계정 잠금 해제/비활성 세션 정책 전체, 인증 감사 전체, 자동저장·그리드 고급 편집, 제출 스냅샷·실제 승인, 출력/이메일/외부 링크, 영업·계약·보고서, 백업 복원. 범위와 계획은 DEVELOPMENT_PLAN.md 및 docs/implementation-checklist.md를 참고하세요.
