# 저장·인증 기반의 범위와 제한

## 연결된 흐름

직원 로그인 → 서버에서 세션·활성 membership 확인 → 거래처·현장 등록/선택 → 견적 계산 미리보기 → 수동 저장 → 서버 검증·재계산 → 견적/버전/행/감사 트랜잭션 → 목록에서 재조회.

세션은 Better Auth DB 세션이며 캐시를 사용하지 않는다. 비밀번호는 Better Auth의 scrypt 해시를 사용하고 공개 가입을 금지한다. 로그인 요청은 IP 기준 60초당 5회 제한한다. TOTP는 사용자별 활성화 방식이며 복구 코드를 지원한다. 세션 최대 8시간, 라이브러리 갱신 주기 15분이며 ‘15분 비활성 자동 로그아웃’ 구현을 의미하지 않는다.

쓰기 API는 설정된 BETTER_AUTH_URL과 Origin이 일치해야 한다. 브라우저는 쿠키를 사용하고 API는 JSON·최대 1MiB 입력을 받는다. 요청의 총액을 신뢰하지 않고 서버 계산 결과를 저장한다. 조회자는 원가 필드를 받지 않는다.

생성 시 requestId UUID를 견적 ID로 사용해 같은 생성 요청 재시도를 구분한다. 수정 시 expectedRowVersion을 조건부 증가시키며 충돌은 409다. 직전 요청의 requestId와 내용 해시가 같으면 같은 결과를 반환한다. 이후 다른 수정이 반영된 과거 요청의 재전송은 충돌로 처리한다. 요청 키는 같은 내용의 네트워크 재시도에만 재사용한다.

## 운영 전 남은 작업

- 실제 PostgreSQL 통합·성능 검증, 운영 환경 비밀키와 HTTPS 설정.
- 전 직원 MFA 등록 강제 정책, 계정별 로그인 실패 잠금·관리자 해제.
- 사용자 관리 UI, 비활성 세션 만료, 로그인 성공/실패·보안 설정 감사 전체.
- 인증 정보 변경 시 기존 세션 정책, 보안 헤더·CSRF·업로드 등 종합 검토.
- 제출 버전 불변성의 DB 제약, 승인·새 차수, 서버 자동저장.
- 백업·복원 및 보존·삭제 정책. 파일 DB 재열기 테스트는 백업 복원 테스트가 아니다.

초기 설정 실행은 이번 세션에서 승인되지 않았다. setup은 로컬 전용 무작위 관리자와 비밀키를 생성하므로 사용자 터미널에서 수행해야 한다. 초기 관리자 파일은 .gitignore 대상이고 운영용 자격 증명이 아니다. 파일 권한은 Windows 상위 폴더의 접근 제어도 확인해야 한다.
